# エンジニアの法則・名言集ページ（Issue #95）

## ゴール

`development/laws.md` に「ソフトウェアエンジニアなら知っておきたい法則・名言」を、**一次資料へのリンクつき**でまとめる。足りないものは X で募集する。

## 方針

- **一次資料主義**: 各項目に「誰の言葉か」「初出（本・論文・エッセイ・RFC・ML 投稿）」「原文リンク」を必ず付ける。原文（英語）を引用し、日本語で意味と使いどころを添える。
- **人が発した言葉だけ**: 実在の人物の発言・著作のみ。フィクションからの引用は入れない。
- **出典の不確かさは隠さない**: 伝聞・二次資料しかないもの（Phil Karlton、Brian Chesky 経由の Paul Graham など）は、そう書く。孫引きされて誤った初出が広まっているもの（正規表現の格言など）は、先行例があることも書く。
- **リンクは実際に開けるものだけ**: 追加前に HTTP ステータスを確認する。

## 収録範囲（Issue #95 で合意）

1. ソフトウェア開発の古典
2. スタートアップ・プロダクト

今回は入れない（将来の追加候補）: 人間・組織・チームの法則（Parkinson、Hofstadter、90-90 ルール、Chesterton の柵、Goodhart）、AI 時代の格言（The Bitter Lesson、Amara の法則、Hyrum の法則）。

## 構成

```

  ├─ はじめに（このページの読み方・出典の書式）

```

各項目の書式:

```
### 見出し（日本語）

> 原文（英語）

**誰** ／ **初出** — [リンク](url)

日本語の説明（2〜4行）。どういう場面で効くか。
```
