# イベント開催の進め方

ミートアップ・発表会・勉強会などを開くときに気をつける点を、時系列の「流れ」と、直前に見返す「チェックリスト」にまとめています。
過去のイベント運営の指示・テンプレートをもとにしています。宴会（懇親会）を開く場合は [宴会の進め方](./party.md) を参照してください。

> 横断する考え方：**文言やメールはテンプレート化して「誰でもできる」状態にする。** 毎回ゼロから書かず、使い回せる形で残す。

## まず、ここがイベントのメイン

**日程・場所・テーマが最重要。** そして、**テーマに沿った登壇者**。
この4つが決まり、良い内容になれば、イベントはほぼ成功。残りは運営の段取りです。企画段階ではまずここに全力を注ぎます。

## 流れ

### 1. 企画（開催の2ヶ月前まで）

まず、以下を決めて固める。決まったものから**マスター情報ページ**（GitHub のイベントページ）に書いていく。

**最重要（イベントのメイン）**

- **テーマ**（イベントの軸）
- **日程・所要時間**（開場・開始・終了の時刻）
- **会場／形式**（現地／オンライン／ハイブリッド）
- **登壇者**：テーマに沿った人選を考え、打診・確保する

**そのほか企画で決めておくこと**

- **目的・ゴール**（何のためのイベントか。達成したい状態）
- **対象者と定員**（**過去のイベント実績からキャンセル率を推測**し、定員・募集人数に反映する。申込＝参加ではなく、no-show を見込む）
- **コンテンツ構成**（基調講演・LT・ハンズオン・パネル・懇親会の有無。CFP の要否）
- **参加費**（無料／有料。有料なら集金方法も）
- **予算と費用負担**（スポンサー・協賛の有無。※お金のやり取りはできるだけしない。例：食事はスポンサーに直接発注してもらい受け取るだけにする）
- **共催団体**（いれば情報共有し、共催で告知する OK を得る）
- **告知媒体**（connpass・SNS・メルマガ・共催先など）
- **配信の有無**（当日中継・録画・後日公開）
- **ハッシュタグ・公式アカウント**
- **運営体制**（幹事と、当日の係の見込み）
- **タイムテーブル案**：企画段階でラフに作っておき、以後更新していく。あると当日の解像度が上がる

**会場まわり（現地の場合）**

- 会場を決めたら予約する。新規会場なら担当者と打ち合わせ・下見をする。
- **会場の入場方法を確認する**（受付・入館手続きの有無、手間の大きさ）。
- **入場に手間がかかるなら、入場時間を制限する**（例：開始前と休憩時のみ入場可）。あわせて、**ランチ時に外出できるか／会場で飲食できるか**を調べておく（外出不可なら各自持ち込みを案内、など）。

決まったら：

- **マスター情報ページ（GitHub のイベントページ）を1つ用意**し、以降の情報はすべてそこに集約する。前日・当日はバタバタするので「そのページを見れば全部わかる」状態を最初から目指す。
- 日程・会場が決まった段階で、**詳細未定でもまず告知する**（SS 内部・SNS・共催先へ）。

### 2. 準備・集客（遅くとも1ヶ月前から）

- 遅くとも**1ヶ月前から集客（告知）を始める。** イベントページ（GitHub／connpass 等）を作って公開する。記載すること：日時・会場・形式・対象・定員・コンテンツ・参加費・申込方法・キャンセル方針・ハッシュタグ・問い合わせ先・アクセス/入館方法（入場時間の制限があれば明記）。
- **定員が埋まるまで SNS で告知を続ける。** 告知文はテンプレート化する。
- 協賛団体・メディアにも声をかける（送り先リストもテンプレート化）。
- 企画で作ったタイムテーブル案を、登壇者が固まるにつれて更新していく。
- 申込ページには、申込ボタンの近くに「**参加できない場合は必ずキャンセル**」「**体調不良以外のキャンセルは1週間前まで**」を明記する。
- **事前アンケートを取る**（当日ではなく事前に）。キャンセル待ちに重要人物がいれば別枠でねじ込める。参加者の属性把握にも使える。項目例：所属・参加動機・懇親会の参加可否・食事アレルギー・**写真掲載の可否**。
- 登壇者との**連絡手段を決める**（人数が多いなら登壇者用のチャンネル）。登壇者へ伝えること：発表時間・資料の形式と提出期限・接続テスト・登壇順。
- 賞品がある場合は、賞を考えて手配する（**領収書を忘れない**）。
- **会場の Wifi・電源の数を確認する。** 足りなければ電源タップ・モバイル Wifi の用意を呼びかける。
- **食料の手配**（ランチ・おやつ・懇親会）。数はキャンセル率を見込んで決める。支払い方法・領収書の宛名・受け取り/返却のフローをドキュメント化して、誰でもできるようにする。
- 備品を用意する：名札・ラベルシール・マーカー・A4 用紙・付箋・筆記具。
- リマインダー（登録時）を送る。

### 3. 1週間前

- 登壇予定者に内容（講演・LT など）を確認し、ページを更新する。資料提出・接続テストも依頼する。
- 参加者に Slack チャンネルの登録を連絡する。
- キャンセルは早めにするよう呼びかける。
- **当日の係分担を決める**（準備・受付・司会・タイムキーパー・ビデオ中継・写真撮影・**SNS 実況**・**Slack を見て現地に伝える連絡係**・**オンライン質問の取りまとめ**・懇親会幹事）。
- **レポート記事の担当を必ず事前に決める。** 当日にメモを取り、事後に記事化してもらう。
- 司会の進行スライド・進行台本を用意する。
- リマインダー（数日前）を送る。

### 4. 前日

- マスター情報ページに、**当日スケジュール・関係者/登壇者の入り時間・会場の入館手順**（QR・来館予約など）・**緊急連絡先**を反映する。
- 当日用意するものを最終確認する（名札・電源タップ・配信機材・賞品・釣銭など）。
- 動画・音声の収録準備をする（機材とテスト）。
- **生配信をする場合、配信 URL（YouTube など）を事前に発行し、参加者へ必ず配布しておく。** 当日に URL が変わるトラブルもあるので、固定 URL の確保・予備リンクの用意に注意する。

### 5. 当日

- 設営：受付・配信・電源・看板をセットする。
- **受付**：名札を渡す。アルコールがある場合は受付で**未成年を確認**し、誤って取らないよう伝える。入場時間を制限している場合は、入場可能な時間を案内する。
- **SNS 実況・写真係**が、リアルタイムで SNS に投稿し、写真を撮る。公式アカウントでも中継する。
- **ハッシュタグを共有し、参加者にも「このハッシュタグでぜひ呟いてください」と案内**して、リアルタイムの実況を促す。
- **オンライン⇔現地の橋渡し**：当日は現地の人が Slack を見られないので、**Slack を見て現地に伝える連絡係**を置く。
- **オンラインからの質問**をスライド系ツール（Slido など）で集め、会場で拾う。
- **記録**：動画を撮って後で公開する。**公開予定がなくても音声は収録しておく**（後で使える）。集合写真・会場写真・レポート用のメモも残す。
- **写真 NG の人への配慮**：事前に写真掲載の可否を確認しておき、撮影時（特に集合写真）には「NG の人は顔を隠す／写らない位置へ」と案内する。
- 登壇者にプレゼン資料を共有してもらう。参加者にレポート（note など）の執筆をお願いする。
- 時間管理はタイムキーパーが担当する。事前に情報共有を済ませ、**当日は議論・交流に集中する**（情報共有だけで終わらせない）。
- 省力化：当日スケジュールの細部は、イベントページの URL を貼って「ここを参照」でもよい。
- リマインダー（当日）を送る。

### 6. 事後

- 片付け・原状回復・忘れ物の確認をする。
- **レポート記事と動画は重要。** 事前に決めたレポート担当が、当日のメモをもとに記事（note など）をまとめる。SS や参加者のレポートを SNS で共有する。
- 動画を編集して公開する。発表資料のまとめページも公開する。
- 経費を精算する（領収書をまとめる）。スポンサー精算がある場合も、お金のやり取りは最小限にする。
- **振り返り**（良かった点・改善点、そして**実際のキャンセル率**）をマスター情報ページに残し、次回のテンプレート・定員設計に反映する。
- 宴会を開く場合は [宴会の進め方](./party.md) を参照。
