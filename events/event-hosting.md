# イベント開催の進め方

ミートアップ・発表会・勉強会などを開くときに気をつける点を、時系列の「流れ」と、直前に見返す「チェックリスト」にまとめています。
過去のイベント運営での指示をもとにしています。宴会（懇親会）を開く場合は [宴会の進め方](./party.md) を参照してください。

## 流れ

### 1. 企画（開催の2ヶ月前まで）

- **概要（日程・会場・コンテンツの骨子）を2ヶ月前までに決める。** ここがすべての起点。
- コンテンツ（LT の有無・CFP の要否を含む）を早めに固める。CFP は必要なら作る。
- **マスター情報ページ（Notion など）を1つ用意**し、以降の情報はすべてそこに集約する。前日・当日はバタバタするので「そのページを見れば全部わかる」状態を最初から目指す。
- スポンサーがつく場合、**お金のやり取りはできるだけしない。** 例：食事はスポンサーに直接発注してもらい、こちらは受け取るだけにする（立替・集金・精算を避ける）。

### 2. 準備・集客（遅くとも1ヶ月前から）

- 遅くとも**1ヶ月前から集客（告知）を始める。**
- **タイムテーブルは案を早めに作り、更新していく。** あると当日の解像度が上がる。
- 申込ページには、申込ボタンの近くに「**参加できない場合は必ずキャンセル**」「**体調不良以外のキャンセルは1週間前まで**」を明記する。
- **事前アンケートを取る**（当日ではなく事前に）。キャンセル待ちに重要人物がいれば別枠でねじ込める。参加者の属性把握にも使える。
- 登壇者との**連絡手段を決める**。人数が多いなら登壇者用のチャンネルを作り、連絡漏れを防ぐ。
- **リマインダーは 登録時 ／ 数日前 ／ 当日 に送る。** 少ししつこいくらいがベター。

### 3. 直前（2週間前〜前日）

- マスター情報ページに、**当日スケジュール・関係者/登壇者の入り時間・会場の入館手順**（QR・来館予約など）を反映する。
- **当日用意するものを揃える**（例：電源タップ）。
- **受付・名札の準備／発行**の段取りを確認し、運営メンバーに引き継ぐ。
- **ランチ／ケータリング**の運用を決める（例：食べながら発表を聞く）。
- **動画・音声の収録準備**をする。

### 4. 当日

- **受付**：名札を渡す。アルコールがある場合は受付で**未成年を確認**し、誤って取らないよう伝える。
- 事前に情報共有を済ませ、**当日は議論・交流に集中する**。時間が限られるので、情報共有だけで終わらせない。
- **記録**：動画を撮って後で公開する。**公開予定がなくても音声は収録しておく**（後で使える）。
- 省力化：当日スケジュールの細部は、イベントページの URL を貼って「ここを参照」でもよい。

### 5. 事後

- **発表資料のまとめページ・レポート記事を公開**する。
- 宴会を開く場合は [宴会の進め方](./party.md) を参照。

## チェックリスト

### 2ヶ月前まで
- [ ] 概要（日程・会場・コンテンツの骨子）を決める
- [ ] コンテンツ（LT・CFP の要否）を固める。必要なら CFP を作る
- [ ] マスター情報ページ（Notion など）を用意する
- [ ] スポンサー費用は「直接発注してもらう」などで、お金のやり取りを避ける形にする

### 1ヶ月前〜
- [ ] 集客・告知を始める
- [ ] タイムテーブル案を作る（以後更新）
- [ ] 申込ページにキャンセル方針を明記する
- [ ] 事前アンケートを用意する
- [ ] 登壇者の連絡手段を用意する（必要なら専用チャンネル）
- [ ] リマインダー（登録時）

### 直前（2週間前〜前日）
- [ ] マスター情報に当日スケジュール・入り時間・入館手順を反映する
- [ ] 当日用意するものを準備する（電源タップなど）
- [ ] 受付・名札の段取りを確認・引き継ぐ
- [ ] ランチ／ケータリングの運用を決める
- [ ] 動画・音声の収録準備をする
- [ ] リマインダー（数日前）

### 当日
- [ ] 受付・名札（アルコールは未成年確認）
- [ ] リマインダー（当日）
- [ ] 動画撮影／音声収録
- [ ] 当日は議論・交流に集中する

### 事後
- [ ] 発表資料のまとめ・レポート記事を公開する
