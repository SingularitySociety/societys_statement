# テストの層（単体〜E2E）と、それを使った安全なリファクタリングの手順を追加する

## ゴール

`development/testing.md` に、初心者が「どのテストで何を守るか」を決め、その層を使って安全にリファクタリングするための方針をまとめる。E2E を含める。既存の [refactoring.md](../development/refactoring.md) §4「どう安全に？」を具体化する位置づけ。

## 方針

- テストの層は四つ：単体 / 結合（ゴールデンテスト）/ E2E（API をまねる・本物につなぐ）/ アプリを起動して手で確かめる
- 中心の原則は「判断は単体で、つながりは E2E で」。どちらか一方では足りない理由を書く
- リファクタリング手順は「外側を E2E で固定 → 切り出し → 単体で固める → 呼び出し側を壊して確かめる」。絡まって単体テストが書けないコードから始める初心者向けに、外側から固定する順にする
- 動きが同じだと示せない切り出しは見送り、理由を残す
- E2E の実例は MulmoClaude（`e2e/` と `e2e-live/` の二本立て、`mockAllApis`、CI での分割と毎日の実行）。リンク先は実物を確認したものだけ
- AI への指示文例とチェックリストを付ける
- README の目次と refactoring.md から相互リンクする
