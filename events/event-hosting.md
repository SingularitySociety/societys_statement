# イベント開催の進め方

ミートアップ・発表会・勉強会などを開くときに気をつける点を、時系列の「流れ」と、直前に見返す「チェックリスト」にまとめています。
過去のイベント運営の指示・テンプレートをもとにしています。宴会（懇親会）を開く場合は [宴会の進め方](./party.md) を参照してください。

> 横断する考え方：**文言やメールはテンプレート化して「誰でもできる」状態にする。** 毎回ゼロから書かず、使い回せる形で残す。

## 流れ

### 1. 企画（開催の2ヶ月前まで）

- **概要（日程・会場・コンテンツの骨子）を2ヶ月前までに決める。** ここがすべての起点。
- 会場は、決めたら予約する。**新規会場なら担当者と打ち合わせ・下見**をする。
- コンテンツ（LT の有無・CFP の要否を含む）を早めに固める。CFP は必要なら作る。
- **共催団体がいれば情報共有し、共催で告知することの OK を得る。**
- **マスター情報ページ（Notion など）を1つ用意**し、以降の情報はすべてそこに集約する。前日・当日はバタバタするので「そのページを見れば全部わかる」状態を最初から目指す。
- スポンサーがつく場合、**お金のやり取りはできるだけしない。** 例：食事はスポンサーに直接発注してもらい、こちらは受け取るだけにする（立替・集金・精算を避ける）。
- 日程・会場が決まった段階で、**詳細未定でもまず告知する**（SS 内部・SNS・共催先へ）。

### 2. 準備・集客（遅くとも1ヶ月前から）

- 遅くとも**1ヶ月前から集客（告知）を始める。** イベント Web ページや connpass 等のイベントページを作って公開する。
- **定員が埋まるまで SNS で告知を続ける。**
- 協賛団体・メディアにも声をかける。
- **タイムテーブルは案を早めに作り、更新していく。** あると当日の解像度が上がる。
- 申込ページには、申込ボタンの近くに「**参加できない場合は必ずキャンセル**」「**体調不良以外のキャンセルは1週間前まで**」を明記する。
- **事前アンケートを取る**（当日ではなく事前に）。キャンセル待ちに重要人物がいれば別枠でねじ込める。参加者の属性把握にも使える。
- 登壇者との**連絡手段を決める**（人数が多いなら登壇者用のチャンネルを作り、連絡漏れを防ぐ）。
- 賞品がある場合は、賞を考えて手配する（**領収書を忘れない**）。
- **会場の Wifi・電源の数を確認する。** 足りなければ電源タップ・モバイル Wifi の用意を呼びかける。
- **食料の手配**（ランチ・おやつ・懇親会）。注文フロー（数・支払い方法・領収書の宛名）はドキュメント化して、誰でもできるようにする。
- 名札・A4 用紙・付箋などの備品を用意する。
- リマインダー（登録時）を送る。

### 3. 1週間前

- 登壇予定者に内容（講演・LT など）を確認し、ページを更新する。
- 参加者に Slack チャンネルの登録を連絡する。
- キャンセルは早めにするよう呼びかける。
- **当日の係分担を決める**（準備・受付・司会・ビデオ中継・写真撮影・タイムキーパー）。
- 司会の進行スライドを用意する。
- リマインダー（数日前）を送る。

### 4. 前日

- マスター情報ページに、**当日スケジュール・関係者/登壇者の入り時間・会場の入館手順**（QR・来館予約など）を反映する。
- 当日用意するものを最終確認する（電源タップなど）。
- 動画・音声の収録準備をする。

### 5. 当日

- **受付**：名札を渡す。アルコールがある場合は受付で**未成年を確認**し、誤って取らないよう伝える。
- ハッシュタグを共有し、公式アカウントで中継する。
- **記録**：動画を撮って後で公開する。**公開予定がなくても音声は収録しておく**（後で使える）。集合写真・会場写真・レポート用のメモも残す。
- 登壇者にプレゼン資料を共有してもらう。参加者にレポート（note など）の執筆をお願いする。
- 事前に情報共有を済ませ、**当日は議論・交流に集中する**。時間が限られるので、情報共有だけで終わらせない。
- 省力化：当日スケジュールの細部は、イベントページの URL を貼って「ここを参照」でもよい。
- リマインダー（当日）を送る。

### 6. 事後

- レポートをまとめて記事（note など）を書く。SS や参加者のレポートを SNS で共有する。
- 発表資料のまとめページを公開する。
- 宴会を開く場合は [宴会の進め方](./party.md) を参照。
